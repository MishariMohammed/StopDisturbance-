# 04 — UX Specification (StopDisturbance)

Owner: UI/UX agent · Status: v1.1 draft · Stack: Next.js (App Router) + Tailwind · Locales: `ar` (default for SA), `en`

**Scope: personal, single-user app.** One owner, their own Gmail + Outlook. No signup, marketing/landing pages, billing, team or multi-tenant UI. The owner is also the only Google test user. LLM = the owner's own DeepSeek API key, with a "Rules only, no AI" mode (§3.6, §4.3).

## 1. Principles

1. **Trust first.** Before asking for any permission, show exactly what we read, store, and never touch. Every screen that touches mailbox data has a visible "What we can see" link (same position on every page; WCAG 3.2.6 Consistent Help).
2. **User stays in control.** Every automated decision (tag, law, channel, draft text) is a *suggestion* the user can change. Default for every company is **unselected**. Nothing is pre-ticked.
3. **Evidence over claims.** No company appears without evidence: email count, first/last seen, 3 example subjects, and the rule that tagged it ("Has `List-Unsubscribe` header", "Order confirmation from noreply@…", "Known data broker"). If we can't show why, we don't show it.
4. **Nothing sends without explicit approval.** Sending requires (a) a reviewed draft, (b) a final confirmation that names the count, mailbox, and recipients, (c) a 10-second undo window after confirm. No auto-send, no "send all" from the company list.
5. **Least data, visibly.** Headers-only scan by default; bodies are never fetched for scanning. Show the data retention countdown on Settings.
6. **Plain language, both languages equal.** Arabic is not a translation afterthought: every string is authored in both; legal terms get a one-line plain explanation.
7. **Reversible where possible, explicit where not.** Keep/Remove decisions, filters, and drafts are reversible. Sent mail is not — so the UI says so in the confirmation.

## 2. Information architecture

```
/                       Redirects: first run → /connect; afterwards → /tracker (or /companies if nothing sent)
/connect                Step 1 — first-run setup: language, your details, AI mode, connect mailboxes
/scan                   Step 2 — scan progress + summary
/companies              Step 3 — review found companies, decide Keep/Remove
/review                 Step 4 — review drafts, approve, send
/tracker                Step 5 — ongoing: replies, deadlines, escalations
  /tracker/[requestId]  Request detail (timeline, thread, next action)
/settings               Accounts, language, notifications, data
  /settings/data        Export my data, erase everything (reset)
(No public pages. The app sits behind a single-owner login — e.g. Auth.js with an allow-list of the owner's
Google/Microsoft email — so nobody else can open it even if they find the URL.)
```

App shell:
- Desktop (≥1024px): top bar (logo, stepper for first run / nav tabs after first run, language toggle `ع | EN`, account menu). Content max-width 1200px.
- After first send, the stepper is replaced by tabs: **Companies · Review (n) · Tracker (n needing action)**.
- Mobile (<768px): bottom tab bar with the same 3 tabs + Settings. Stepper collapses to "Step 2 of 5" text + progress bar.
- First-run stepper: `Connect → Scan → Choose → Review → Track`. Steps are links only when reachable (can't jump to Review with zero drafts).

Global components on every app page: `HelpLink("What we can see")`, `LanguageToggle`, `ConnectedAccountsChip` (shows `2 mailboxes`, click → popover listing addresses + "Disconnect").

## 4. Onboarding and consent

### 4.1 Sequence

1. First visit → `/connect` first-run setup. The first OAuth (`openid email profile`) signs the owner in; any email not on the owner allow-list (env `OWNER_EMAILS`) is rejected. No signup screen.

## 5. Company list design

### 5.1 Grouping
- One row per **company**, not per sender: group by registrable domain (eTLD+1) + known brand map (e.g. `noon.com`, `noon.ae`, `mail.noon.com` → noon). Show all domains in the drawer.
- User can `Split` (wrong grouping) or `Merge` (drag-free: select 2 rows → "Merge into one"; WCAG 2.5.7 forbids drag-only).
- Ignore personal senders (gmail.com/outlook.com individuals) and the user's own employer domain — never listed.
- Default view groups visually into three sections by suggested action: **Likely hold your data** (account/order/booking signals), **Marketing only**, **Data brokers (from our list)**. Sections are collapsible headings (`<h2>`), not separate pages.

### 5.2 Filters, sort, search
- Filter chips (single-select category, shows counts): `All · Ads · Holds data · Both · Brokers`.
  - Ads = has `List-Unsubscribe` or marketing classifier. Holds data = transactional/account signals. Both = intersection. Brokers = matched to broker registry (CA/VT registries + curated list) — may have 0 emails.
- Secondary filters (dropdowns): Decision (Undecided / Remove / Unsubscribe / Keep), Mailbox, Law (PDPL / GDPR / CCPA / Unknown), Confidence (High / Medium / Low), Last seen (≤30d / ≤1y / older).
- Sort: Most emails (default) · Most recent · Oldest first-seen · A–Z (locale-aware collation `Intl.Collator(locale)`).
- Search: debounced 200ms, matches company name (AR and Latin), domain, sender address. Arabic search normalizes alef/hamza/ta-marbuta/tatweel.
- Filters persist in URL query (`?cat=data&sort=recent`) so back/forward and sharing a view work.

### 5.3 Bulk select
- Row checkbox (target ≥24×24 CSS px, row also clickable via label). Checkbox is always visible.
- Toolbar `SelectAllMenu` (split checkbox): "Select this page (25)" · "Select all 46 matching filter" · "Select none". Select-all never selects across filters the user can't see; the count is always stated.
- `BulkActionBar` appears only with ≥1 selected, sticky to bottom, announces "12 selected" via `aria-live`.
- Bulk actions only **mark decisions**. They never send. The only forward action is `Create N drafts` which leads to /review.
- Shift-click range selection on desktop; on mobile, long-press enters selection mode.

### 5.4 Evidence drawer
Contents in fixed order: Why it's here (signals with counts) → Seen range → Mailboxes → 3 example subjects (truncated at 80 chars, user can hide subjects globally) → Law we'll use + "why?" (e.g. "Company is Saudi-registered (.sa domain, CR in footer)" or "You're in Saudi Arabia, they serve SA customers") → Contact channel + source + verified date → Confidence → Report wrong.
- Desktop: end-side panel 420px, list stays interactive. Mobile: bottom sheet at 85% height. Focus moves into drawer on open, returns to the row on close; `Esc` closes.

### 5.5 Confidence indicator
- 3-step meter `●●●` High / `●●○` Medium / `●○○` Low + text label (never color alone).
- Definition shown on hover/tap: High = 3+ independent signals agree; Medium = 2; Low = 1 signal or fuzzy name match.
- Low-confidence rows cannot be bulk-marked Remove: they're skipped with a notice "3 low-confidence companies skipped — review them individually."

### 5.6 Keep vs Remove
- Three explicit decisions per row, segmented control, default **none** (Undecided):
  - **Keep** — "I still use them." Row dims, moves to Kept section; never contacted.
  - **Unsubscribe only** — stop marketing, keep account. Uses one-click if available, else a stop-marketing letter.
  - **Remove my data** — deletion + stop-marketing request.
- If a company has recent account/order signals (≤90 days) and user picks Remove: inline warning, not modal: "You ordered from noon 9 days ago. Deleting your data may close your account and order history." with `[Unsubscribe only instead]`.

### 5.7 Preventing accidental mass-sending
1. Nothing pre-selected; no "Remove all" button anywhere.
2. Bulk mark-Remove >25 companies shows a confirmation naming the number and the 3 biggest names.
3. Company list → Review is a separate step; sending exists only on /review.
4. Send confirmation lists count, sending mailbox, and recipients (§6.5).
5. Daily send cap per mailbox (default 50) to protect the user's sender reputation; UI shows "Sending 50 today, 12 tomorrow".
6. 10-second undo after confirm (server holds the queue).
7. All bulk actions are undoable via toast `Undo` for 10s.

- `EscalationWizard`: (1) which regulator (SDAIA for PDPL; national DPA for GDPR via lookup; California Privacy Protection Agency / AG for CCPA); (2) generated complaint summary with timeline + evidence (sent date, no reply, emails still received); (3) `[Open regulator portal ↗]` + copy buttons; (4) "I filed it" + reference number → Escalated. ## 11. RTL rules

1. Set `<html lang="ar" dir="rtl">` from the locale route (`/ar/...`, `/en/...`); never toggle with CSS alone.
2. Tailwind: use **logical utilities only** — `ms-*/me-*`, `ps-*/pe-*`, `start-*/end-*`, `text-start/text-end`, `border-s/border-e`, `rounded-s/rounded-e`. Lint rule bans `ml-/mr-/pl-/pr-/left-/right-/text-left/text-right` in `app/` and `components/`.
3. Use `rtl:` variant only for icon flips: `rtl:-scale-x-100` on directional icons.
4. **Mirror:** back/next arrows, chevrons in drawers/accordions, send icon, progress bars and countdown bars (fill from start side), stepper order, drawer side (opens from the end side = left in Arabic), breadcrumb separators, list-item "▸".
5. **Don't mirror:** numbers, email addresses, URLs, domains, Latin brand names, logos, checkmark ✓, clock/timer icons, media play, charts' numeric axes, the Google/Microsoft buttons.
6. Mixed content: wrap Latin names/emails/domains in `<bdi>` or use `dir="ltr"` spans; inputs for email/URL get `dir="ltr"` always. Draft editor and subject lines use `dir="auto"`.
7. Numerals: default Western digits (0–9) in both locales for dates, counts, and legal deadlines (common in Saudi digital products and avoids mismatches in letters); Settings offers Arabic-Indic (٠–٩). Format with `Intl.NumberFormat('ar-SA', { numberingSystem: 'latn' | 'arab' })`. (Copy tables above show Arabic-Indic for illustration of the toggle.)
8. Dates: `Intl.DateTimeFormat('ar-SA-u-ca-gregory')` by default; Hijri via `-u-ca-islamic-umalqura` as optional secondary.
9. Fonts: Arabic `IBM Plex Sans Arabic` (fallback `Noto Sans Arabic`, `Tahoma`); Latin `Inter`. Never apply letter-spacing to Arabic; never use italic for Arabic (use weight for emphasis). Arabic body text one step larger visually: use `text-[1.0625rem]` equivalent via `lang` selector.
10. Truncation: ellipsis appears at the end side automatically with `text-overflow: ellipsis` when `dir` is correct — verify for mixed strings.
11. Keyboard shortcuts J/K stay the same letters; arrow-key navigation in segmented controls follows visual direction (Right arrow = previous in RTL).

## 14. UX success metrics

| Metric | Definition | Target |
|---|---|---|
| Setup time | First visit → both mailboxes connected | < 3 min |
| Reconnect friction | Gmail weekly reconnects that happen before token expiry (no gap in reply tracking) | ≥90% |
| Time to first scan result | Connect → first company visible | < 3 min |
| Decision coverage | Companies with a decision / companies shown | ≥50% in first session |
| Evidence engagement | Sessions opening ≥1 evidence drawer | ≥40% (trust signal) |
| Misclassification reports | "Not a company / wrong grouping" per 100 companies | <3 |
| Keep ratio | Keep / decided — sanity check we're not pushing deletion | 15–40% healthy |
| Draft edit rate | Drafts edited before approve | 10–30% (higher = bad drafts; ~0 = not reading) |
| Undo rate | Sends undone within 10 s / sends confirmed | <3% (higher = confirmation unclear) |
| Send success | Requests delivered without bounce/error | ≥95% |
| Response rate | Requests with any company reply within deadline | Track by law; baseline |
| Completion rate | Completed / sent at deadline+30 days | ≥50% |
| Overdue → action | Overdue requests where user sends reminder or escalates within 7 days | ≥40% |
| Mail reduction | Marketing emails/week from "Remove/Unsub" companies, 30 days after vs 30 days before | −70% |
| AI vs rules quality | Edit rate and misclassification reports, AI mode vs Rules-only mode | Decide if AI is worth its data cost |
| DeepSeek payload compliance | AI calls containing a field outside the allowed list (automated check on the call log) | 0 |
| Accessibility | axe violations (serious/critical) in CI | 0 |
| Erase completeness | After "Erase everything": provider tokens revoked + DB empty | 100%, verified by test |
